La propuesta en una pantalla

El frente es uno; los menús, bandejas, datos y acciones cambian por perfil y alcance. IA, SAP, API y automatizaciones son actores técnicos, no perfiles de persona.

10dominios de permiso

1catálogo de acciones
Decisión de diseño propuesta: proveedor y seller no necesitan perfiles distintos. Comparten Catalogador externo; el alcance de negocio y organización cambia el flujo permitido. Tampoco se crean cinco perfiles para Legal, Sostenibilidad, VAS, Logística y E-commerce: comparten Dueño de sección y se limita el grupo de atributos.

Cómo funciona el permiso

Permiso efectivo = perfil + acción + alcance + tarea vigente. Las cuatro condiciones deben cumplirse.

  • Separar perfil y alcance. El perfil dice qué clase de acción puede hacer; el alcance limita dónde: negocio, organización, categoría, sección, sede o canal.
  • Componer perfiles. Una persona puede tener más de un perfil. No se crea un “superperfil” nuevo por cada combinación.
  • Denegar por omisión. Si una acción no aparece concedida y dentro del alcance, se rechaza.
  • Separar trabajar de decidir. Quien captura no obtiene automáticamente permiso para aprobar. Administrar usuarios tampoco concede autoridad sobre productos.
  • No usar estatus como permiso. El estado crea una tarea; el perfil y el alcance deciden quién puede ejecutarla.
  • Validar dos veces. El frente oculta lo no permitido, pero el módulo dueño vuelve a validar cada acción.
  • Auditar decisiones. Aceptar, rechazar, cancelar, reasignar, cambiar reglas y administrar accesos dejan quién, cuándo, antes, después y motivo.

Base para construirlo

Ratificar actividades. Revisar esta lista por área y eliminar o dividir sólo donde cambie la separación de funciones.
Congelar el catálogo de acciones. Cada botón o proceso sensible debe apuntar a una acción estable: recurso.acción.
Definir alcances. Negocio, organización, proveedor/seller, categoría, grupo de atributos, canal, sede y ambiente se asignan aparte del perfil.
Crear plantillas de perfil. Los 18 perfiles son plantillas versionadas; una persona puede recibir varias, con vigencia y motivo.
Aplicar en pantalla y dominio. El frente esconde menús y botones; el servicio dueño vuelve a autorizar la acción y el alcance.
Probar negaciones. Cada acción crítica necesita pruebas de “puede” y “no puede”, incluida otra organización, otro negocio y una tarea no asignada.
Auditar y recertificar. Registrar decisiones y revisar periódicamente membresías, privilegios no usados y combinaciones incompatibles.
